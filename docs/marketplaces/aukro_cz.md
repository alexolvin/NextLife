# Aukro.cz (`aukro_cz`) — план подключения

Решение (ТЗ M1 A.2): рекомендуемый набор. Поиск — `DIRECT` (ремон); публикация, правка, снятие, переписка, состояние — `API`.

## Документация API (первая задача, предъявлена 2026-10-03)

- **Спецификация OpenAPI 3.0.4, «Aukro Public API» v2.0**: `https://api.aukro.cz/assets/openapi.yaml`, получена 2026-10-03, 175 006 байт. Артефакт: `.a/reports/m1/probes/2026-10-03/aukro_openapi.yaml`.
- **Production-сервер** (из блока `servers` спецификации): `https://aukro.cz/api/v2`.
- **Получение ключа** (секция `Authentication` спецификации): «Access to the Aukro Public API requires OAuth 2.0 access_token and an API key. First step is to obtain client_id and client_secret. **Contact our support**» — адрес `obchod@aukro.cz`. Методы: OAuth2 `client_credentials` (сервер-к-серверу) и `authorization_code` с PKCE; плюс заголовок `X-Aukro-Api-Key` («API Key from Aukro»). Устаревший `POST /authenticate` (username/password → JWT) помечен deprecated, «May be removed after: 31.12.2026».
- **Границы API** (описание в спецификации): «Unlike its predecessor webAPI, it does not provide any functionality for both bidding and buying» — Public API ориентирован на продажу; торги/покупка не покрываются.
- **Ключевые эндпоинты** (из спецификации): `POST /offers-v2`, `GET /offers-v2/{id}`, `GET /offers-v2/list`, `POST /offers/{id}/terminate` (снятие), `/images`, `/categories`, Webhooks (`newOrderSubmitted` v3, `orderWithdrawalRequest`) — источник состояний сделки и подтверждения оплаты.
- Членство changelog: последняя запись 31.08.2026 — спецификация живая.
- **Вывод для частного продавца**: ограничения «только для корпоративных» в документации не заявлено; ключ выдаётся по обращению в поддержку. Окончательное подтверждение — при получении ключа Владельцем (подтверждение 4). Если на практике доступ частному продавцу откажут — публикация на Aukro получает `BLOCKED-EXTERNAL` с этой причиной, поиск продолжает работать; перенос публикации на `DIRECT` в обход условий API запрещён (ТЗ M1 A.4).

## Живые пробы (2026-10-03)

- `https://aukro.cz/vysledky-vyhledavani?text=thinkpad` → 200, **без редиректа**, SSR-выдача 4 карточки (`auk-basic-item-card` / `auk-item-card-title` / `auk-item-card-price`), цены извлечены (1 388 / 1 257 / 262 CZK).
- `https://aukro.cz/vysledky-vyhledavani?text=RTX+3090` → цепочка 301 → **SEO-лендинг** `https://aukro.cz/lp/nejkvalitnejsi-rtx-3090` (4 карточки, не полная выдача).
- **Факт: SEO-редирект зависит от запроса** — для части запросов площадка подменяет выдачу лендингом. Final URL после редиректов фиксируется в каждом артефакте пробы и в канарейке (редирект на неизвестный адрес = `BLOCKED`, мутация D.3-3).
- Текущие селекторы конфига `.list-item` / `.price-tag` в живой разметке отсутствуют (0 совпадений).
- Артефакты: `.a/reports/m1/probes/2026-10-03/aukro_cz.html`, `summary.json`, `aukro_openapi.yaml`.

Канал по сценариям: поиск `DIRECT` (ремон) / публикация `API` / правка цены `API` / снятие `API` / переписка `API` (то, что покрывает спецификация; не покрывается — помечается, см. ниже) / состояние сделки `API` (Webhooks)

Доступы от Владельца: учётная запись Aukro; ключ API (после предъявленной документации — подтверждение 4).

Технические шаги:
1. Документация API предъявлена (выполнено 2026-10-03, раздел выше).
2. Ремонт поиска `DIRECT`: карта маршрутов + селекторы в конфиг (как Sbazar); фиксация final URL; обработка query-зависимого SEO-редиректа (лендинг ≠ выдача — распознаётся и помечается).
3. Фикстуры + контрактные тесты разбора.
4. Канарейка поиска с проверкой final URL.
5. Клиент `API` (OAuth2 client_credentials + `X-Aukro-Api-Key`), секреты — через SecretRef.
6. Публикация `POST /offers-v2` с доказательством (`external_id`/`external_url` + снимок, Ч-5).
7. Правка цены, снятие `POST /offers/{id}/terminate`.
8. Подписка Webhooks → состояния сделки (`PAID` — только по событию площадки).

Покрытие сценариев: поиск — после шага 2 (уже 4 карточки на живую). Публикация/правка/снятие/состояние — после шагов 5–8. **Не покрывается**: торги и покупка (Public API их не предоставляет — факт из спецификации); переписка с покупателями — спецификация её в эндпоинтах не содержит: помечено как **непроверенно**, до подтверждения в документации Aukro сценарий переписки на Aukro считается недоступным (Ч-6).

Верификация: пробы с final URL (Ч-1); контрактные тесты; API-вызовы — `external_id` + снимок; Webhook-события — сырые payloads в артефактах.

Риски:
- комиссии площадки — в `capabilities` с источником и датой; на 2026-10-03 источник комиссий **не получен — значение непроверено** (Ч-6);
- аукционный формат — отдельная ветка состояний лота (торги идут / завершены без ставок);
- SEO-редирект на лендинг — канарейка сверяет final URL;
- OAuth2-токены — только через SecretRef, в логах и отчётах не печатаются.

Усилия: M

Зависимости: поиск — без внешних ресурсов (ремон); публикация — ключ API (подтверждение 4, выдаётся Aukro по заявке через obchod@aukro.cz).

Класс блокировки: поиск — снимается ремонтом; публикация — снимается ресурсом (ключ API); если Aukro откажет частному продавцу — `BLOCKED-EXTERNAL` навсегда для канала `API`, поиск остаётся.
