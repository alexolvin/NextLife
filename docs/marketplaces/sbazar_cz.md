# Sbazar.cz (`sbazar_cz`) — план подключения (ремон)

Решение (ТЗ M1 A.2): минимальный набор. Канал `DIRECT` по всем сценариям; публикация — в сессии Seznam.

**Живые пробы 2026-10-03**:
- текущий маршрут коннектора `https://www.sbazar.cz/hledat/{q}` → **HTTP 404** (сломан);
- реальный маршрут `https://www.sbazar.cz/hledej/{q}` → HTTP 200, final URL без редиректов, без антибота, SSR-выдача: 46 объявлений (`ul[data-test=offer-list]` → `li[data-offer-id]` → `a[href*="/inzerat/"]`, цена — `<b>`).
- Артефакты: `.a/reports/m1/probes/2026-10-03/sbazar_cz.html` (сырой HTML реального маршрута), `summary.json`.
- Факт о разметке: текущие селекторы конфига `.c-item` / `.c-price` в живой разметке отсутствуют (0 совпадений).

Канал по сценариям: поиск `DIRECT` (сейчас сломан — ремонт) / публикация `DIRECT` в сессии Seznam / правка цены `DIRECT` / снятие `DIRECT` / переписка `DIRECT` / состояние сделки `DIRECT`

Доступы от Владельца: учётная запись Seznam (вход на сайт — один раз, выполняет Владелец; NextLife хранит только профиль браузера).

Технические шаги:
1. Живая проба текущих маршрутов поиска и карточки, сохранение сырого HTML с датой (выполнено 2026-10-03, шаг 1).
2. Обновление карты маршрутов в `config/marketplaces/sbazar_cz.yaml` (`/hledat/` → `/hledej/`), а не в коде.
3. Обновление селекторов там же (фактические: карточка `li[data-offer-id]`, ссылка `a[href*="/inzerat/"]`, цена `b`).
4. Перезапись фикстур поиска и карточки по новой разметке (с датой).
5. Контрактные тесты разбора на новых фикстурах.
6. Включение ежедневной канарейки (часть D).
7. Публикация: Playwright с сохранённым профилем Seznam; правка цены, снятие, переписка, состояние — в той же сессии.

Покрытие сценариев: после шагов 1–5 — поиск и разведка (46 листингов на живую по «thinkpad», 22 по «RTX 3090»). После шага 7 — полный цикл. Не покрывается: ничего при живой сессии; при истечении сессии — `BLOCKED` с уведомлением, повторный вход агентом не выполняется.

Верификация: контрактные тесты на фикстурах (CI); живые пробы с датой (статус, Ч-1); канарейка — ежедневный артефакт + уведомление при дрейфе; публикация — `external_url` + снимок (Ч-5).

Риски:
- смена вёрстки Seznam — канарейка (схема: заголовок/цена/валюта/ссылка/дата);
- истечение сессии — переход в `BLOCKED` с уведомлением, а не повторный вход агентом;
- Seznam CMP при смене UA — фиксировать UA/куки из живой пробы в конфиг.

Усилия: M

Зависимости: ремонт — без внешних ресурсов (начат); публикация — учётная запись Seznam (подтверждение 2).

Класс блокировки: поиск — снимается ремонтом (в работе); публикация — снимается ресурсом (Seznam-аккаунт).
