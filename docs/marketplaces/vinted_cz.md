# Vinted (`vinted_cz`) — план подключения (вторая очередь)

Решение (ТЗ M1 A.2): рекомендуемый набор. Канал `ANDROID` по **всем** сценариям. `DIRECT` закрыт DataDome навсегда (правило A.1: антибот-защита на `DIRECT` закрывает канал навсегда — не обходится и не «пробуется снова»).

**Живые пробы 2026-10-03**:
- web-каталог `https://www.vinted.cz/catalog?search_text=thinkpad` → 200, но **0 объявлений в сыром HTML** (3 788 516 байт; каталог клиентского рендера — листинги загружаются JS-запросами);
- API `https://www.vinted.cz/api/v2/items?search_text=thinkpad` → **403** (DataDome).
- Артефакты: `.a/reports/m1/probes/2026-10-03/vinted_cz.html`, `summary.json`.

Канал по сценариям: поиск `ANDROID` / публикация `ANDROID` / правка цены `ANDROID` / снятие `ANDROID` / переписка `ANDROID` / состояние сделки `ANDROID`

Доступы от Владельца: выделенный Android-телефон (Android 12+; требования — B.2); приложение Vinted, залогиненное самим Владельцем; физический узел с USB для adb-сервера + адрес в Tailscale; письменное принятие риска ограничения учётной записи (подтверждение 7); суточный лимит действий (подтверждение 8).

Технические шаги: по плану части B (B1–B8) поверх ADB + `uiautomator2`:
1. B1 — удаление заглушки моста, модель конфига ANDROID-канала;
2. B2 — транспорт к удалённому adb-серверу по Tailscale, `health()`;
3. B3 — глобальный мьютекс в БД, последовательная очередь `android`;
4. B4 — слой доказательств (PNG + дамп иерархии + версия приложения + метки времени на каждом вызове);
5. B5 — распознаватель экранов Vinted (эталоны ключевых экранов; неизвестный экран → `BLOCKED`);
6. B6 — `app_state`, `search`, `read_listing` (итерация 1 — только чтение);
7. B7 — встраивание в разведку (отчёт с меткой канала);
8. B8 — канарейка Vinted.

Итерации (B.4): 1 — только чтение (`health`, `app_state`, `search`, `read_listing`); 2 — `create_listing`, `update_price`, `archive_listing` для одного дешёвого предмета с отдельным письменным согласием; 3 — переписка и `read_order`; 4 — Facebook.

Покрытие сценариев: поиск, чтение объявления, публикация, переписка, состояние сделки. **Оплата и доставка проходят через Vinted**: переход в `PAID` выполняется по подтверждению площадки, снятому со скриншота экрана заказа (`read_order`). Не покрывается: торги (их на Vinted нет); встроенный выбор перевозчика Vinted не совпадает с конструктором доставки NextLife — для Vinted конструктор показывает только варианты площадки.

Верификация: каждый вызов моста — снимок экрана + дамп иерархии + версия приложения + метки времени (B.3: результат без доказательства = неудача); `create_listing` — `external_url`/`external_id` + снимок опубликованного объявления (Ч-5); канарейка — ежедневный артефакт.

Риски:
- ограничение учётной записи при автоматизированной работе приложения — меры B.6 (официальное приложение, учётная запись Владельца, человеческий темп, суточные лимиты, утверждения); риск остаётся и принят Владельцем письменно;
- обновление приложения ломает распознавание — мост в `BLOCKED` до канарейки на новой версии (B.2, B8);
- отключение кабеля/перезарядка — штатные события → `BLOCKED` с уведомлением.

Усилия: L

Зависимости: выделенный телефон + узел с adb (подтверждения 5, 6); до их появления шаги B2, B6, B7, B8 — `BLOCKED-EXTERNAL`; B1, B3, B4 и тестовая часть B5 выполняются без телефона.

Класс блокировки: `DIRECT` — навсегда (DataDome 403, факт пробы 2026-10-03); `ANDROID` — снимается ресурсом (выделенный телефон + учётная запись Владельца).
